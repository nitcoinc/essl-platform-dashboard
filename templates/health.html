Recovery

  1. Check backups: docker compose run --rm backup python -m essl_hub.backup status
  2. See snapshots in R2: docker compose run --rm backup python -m essl_hub.backup list
  3. Lost or corrupt database: stop the stack, move essl.db, essl.db-wal and essl.db-shm aside, then docker compose run --rm backup python -m essl_hub.backup restore (add --key <key> for an older snapshot). Everyone signs in again afterwards.
  4. Blocked, "different database": restore takes the bucket's database; docker compose run --rm backup python -m essl_hub.backup adopt makes this database the owner instead.
  5. Collector dead-lettered punches stay in the spool's dead table; nothing is dropped.

The full runbook is in the README, section "Recovery".
